# ROI 模型共享操作说明

本功能新增于普通版 `EmbeddingTest` 源码，尚未重新打包到现有 EXE。请先使用修改后的源码运行；正式部署前重新打包并验证。

## 选择模型来源

新订单和原有订单都可使用，无须重新建单。在检测项表中选中一个 ROI，展开右侧独立的“模型来源”区域，选择使用方式后点击“应用模型来源”。它与“算法参数”一样可以点击标题展开或收起，切换 ROI 和刷新界面不会自动展开。

右侧图片列表和底部训练、测试操作保持固定。窗口空间不足时，中间的算法参数、检测工具与模型来源区域可上下滚动；展开设置不会再把测试按钮挤出窗口。

也可以点击“检测工具”标题右侧的“模型来源…”快捷按钮，打开独立设置窗口。关闭窗口不会自动应用尚未保存的选择。画出的 ROI 始终表示当前检测位置，引用模型不会沿用训练时的 ROI 坐标。

在页面内改好模型来源后，点击“标定当前工具”或“训练全部”也会先验证并保存当前选择，再开始训练。共享组名或公共模型版本未选完整时会提示补齐，不会继续按旧的独立模式训练。标定完成后仍保留原来的共享绑定。

算法参数中的“工具”仍可切换。使用共享组或公共模型时，主动切换到其他工具会把当前 ROI 改为独立训练；已发布的公共模型不变。继续引用公共版本时，其判定参数仍使用发布时的固定设置。

| 使用方式 | 样本与训练 | 适用范围 |
| --- | --- | --- |
| 独立训练 | 当前 ROI 自己提供 OK、NG 样本 | 外观或判定标准不同的区域 |
| 同订单组共享 | 组内已标注 ROI 的样本合并，整组合计有 OK、NG 即可 | 同一订单、同一相机、同一算法的同类区域 |
| 引用公共模型 | 当前 ROI 不需要准备训练样本，使用选定的固定版本 | 当前订单或其他订单复用已发布模型 |

旧订单默认保持独立训练。测量工具不使用上述 OK/NG 模型共享。

## 同订单只训练一个区域

1. 画好所有同类 ROI，并为它们选择“同订单组共享”。
2. 在“共享组”中输入或选择同一个组名，例如“针外观”，逐个点击“应用模型来源”。
3. 只为其中一个 ROI 准备并标注有代表性的 OK、NG 样本；其他 ROI 可以没有训练标注。
4. 执行训练。系统按组汇总样本，同一个组只训练一次。
5. 使用测试图片检查各 ROI。检测结果仍按每个 ROI 分别显示。

请先设置共享组再训练。已有独立模型可以直接发布到公共库，再由其他 ROI 引用，不必为了共享而重新准备样本。

共享组单独保存在当前订单中。即使组内所有 ROI 都改为独立训练或引用公共模型，原共享组和已训练模型仍会保留。需要恢复时，选择“同订单组共享”，从下拉框选回原组并应用；对应算法的模型已存在时可直接测试，无须重新训练。旧订单会从已有模型文件、订单备份或公共库中的来源信息恢复可确认的历史组名。

不同学习工具的模型分别保存。例如只训练过“均衡学习工具”的共享组，改用“高精度学习工具”时会立即显示红色“未训练（共享组：…）”；需要为高精度工具重新训练，或切回原来的均衡工具使用原模型。即使没有选中 ROI，切换工具也会刷新全部相关区域的状态。单图和批量测试开始前会检查共享模型是否就绪，缺少模型时提示具体共享组与工具。

## 跨订单引用

1. 在源订单选择已训练的独立模型或组模型，点击“发布到公共库”。
2. 选择“新建公共模型”，输入名称，完成发布。
3. 在目标订单画好 ROI，选择“引用公共模型”，在“公共模型 / 版本”中选择刚发布的版本，点击“应用模型来源”。必要时先点击“刷新公共库”。
4. 状态显示模型可用后直接测试；目标 ROI 无须补齐 OK、NG 训练样本。

公共版本保存模型数据及发布时的判定参数。训练源订单被重新训练或删除后，已发布的版本仍可使用。引用区域应具有相近的目标外观、方向、尺度和成像条件，并使用相同的 OK/NG 定义；请在目标订单用实际图片验证效果。

## 版本更新与备份

公共版本只读。需要更新时，在源订单训练本地模型，再次点击“发布到公共库”，选择原公共模型以生成新版本，例如从 `v000001` 增加为 `v000002`。同名新建模型不会自动合并。

公共模型列表同时显示名称、版本、模型标识和工具。选择后，下方显示来源订单、相机 / ROI、发布时间（UTC）和完整模型标识；列表项悬停提示中也有相同详情。模型标识相同、版本不同，表示同一个模型的不同版本；名称相同、模型标识不同，表示两个独立模型。短标识出现相同前缀时会自动加长，以便区分。

例如 `PINTEST / v000001 [a6af0dba]` 与 `PINTEST / v000002 [a6af0dba]` 属于同一个模型；`PINTEST / v000001 [b7cd182e]` 则是另一个同名模型。发布入口中的“发布新版”也显示对应标识、当前最新版本和来源，确认后才会为该模型创建下一版本。

已引用的订单保持原版本。需要升级的 ROI 应明确选择新版本并应用；不会自动追随最新版本。缺失或损坏的公共版本会显示不可用，不会自动换用其他模型。

源码运行时，公共库位于 `EmbeddingTest/.qr_session/model_library`，与各订单目录并列。打包运行时，位于程序可写根目录的 `.qr_session/model_library` 下：通常为 EXE 同目录的 `EmbeddingTest/.qr_session/model_library`；没有 `EmbeddingTest` 子目录时为 EXE 同目录的 `.qr_session/model_library`。

新程序启动时会将原 `model_library` 中有效的公共版本校验后复制到新位置，保持模型标识和版本号不变，订单引用无须修改。旧目录保留为兼容备份，后续新程序发布的版本只写入新位置。迁移不会覆盖新位置已有的不同内容版本。

`model_library` 是系统保留目录，不会作为订单显示，也不能作为订单新建、复制、打开或删除。

备份、迁移或更新程序时，保留完整的 `.qr_session` 文件夹即可同时保留订单和公共模型库。仅复制其中一个订单目录时，仍需同时带上 `.qr_session/model_library`，才能保留其引用的公共版本。不要手动修改或覆盖已发布版本中的文件。

## 标准学习工具

普通版新增“标准学习工具”，对每个 ROI 的裁剪图片进行 OK / NG 分类。它使用分类训练和 ONNX 推理，ROI 位置仍由原有模板匹配或 NCC 定位提供。

在“算法参数 → 工具 → 学习工具”中选择“标准学习工具”，可设置训练轮数、训练批量及 NG 概率阈值。NG 概率达到阈值时判为 NG。原有学习工具的 proto / topk、margin 参数不参与此工具的判定。

支持独立训练、同订单组共享及跨订单公共模型引用。每个训练任务至少需要 2 个 OK 和 2 个 NG 裁剪样本；共享组按整组合计，同一张图片中不同 ROI 的有效标注分别计数。选中组内任意成员标定当前工具，会合并同组所有已启用且有有效标注的 ROI 样本，训练一次。新增成员在加入组后，需要重新训练才能把其样本纳入已有模型。

本地模型在订单目录保存 `.pt`、`.onnx` 和分类元数据 `.json`。发布到公共库时，固定版本保留 ONNX、分类元数据及 NG 阈值；引用区域不需要重新训练。

源码运行需要安装 `requirements.txt` 中的依赖，基础权重放在 `res/models/yolov8n-cls.pt`。完整版及 Lite 版打包配置均已包含分类依赖和资源；已有 EXE 需要重新打包才能显示新工具。
