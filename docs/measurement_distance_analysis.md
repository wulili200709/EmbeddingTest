## 背景

当前产品 `1571429` 的 cam1 同一个产品连续拍摄了 40 张图。运行界面里距离测量结果出现约 3-4 像素，极端情况下接近 6 像素的波动。

实际需求是模拟卡尺测量两个面的宽度，也就是测两个面之间的间隙/宽度，而不是做数学上两条无限直线的最短距离。

## 当前算法的问题

当前程序是：

1. 左 ROI 找边缘点，拟合左线。
2. 右 ROI 找边缘点，拟合右线。
3. 距离测量工具根据两条线段计算距离。

问题在于：两个 ROI 高度很大，约 1500 px。左线只要有 0.2° - 0.3° 的角度变化，投影到整个高度范围后就会产生几像素级的距离变化。

这不是产品本身真的变宽/变窄，而是“拟合线角度抖动 + 距离定义”导致的测量波动。

另外，二维平面中两条不平行的无限直线会相交，严格数学最短距离为 0。因此对不平行线，必须定义一个工程测量方式，不能只说“线到线距离”。

## 讨论过的几种计算方式

### 方式 1：边缘点 x 中位数相减

逻辑：

1. 左右 ROI 找边缘点。
2. 取左右边缘点共同覆盖的 Y 区间。
3. 分别统计左、右边缘点的 x。
4. `distance = median(x_right) - median(x_left)`。

优点：

- 对毛刺、反光、局部缺口最稳。
- 在这 40 张图上，距离范围约为 1.07 px，明显比当前 5.91 px 稳定。

缺点：

- 它更像统计宽度，不是严格的两条拟合线几何测量。
- 给现场解释时不如“卡尺沿法线测量”直观。

### 方式 2：固定 Y 高度横向距离

逻辑：

1. 拟合左右两条线。
2. 指定一个高度 `y_mid`。
3. 计算 `x_right(y_mid) - x_left(y_mid)`。

优点：

- 简单、容易解释。
- 对竖直边宽度测量符合直觉。

缺点：

- 只取一个高度，容易受该高度附近局部边缘状态影响。
- 如果产品有效测量区上下变化明显，单点代表性不够。

### 方式 3：共同 Y 区间内拟合直线 + 多 Y 采样

逻辑：

1. 左右 ROI 找边缘点。
2. 取两边共同覆盖的 Y 区间。
3. 只用共同 Y 区间内的点重新拟合左线和右线。
4. 在共同 Y 区间内采样多个 y。
5. 计算每个 y 上的 `x_right(y) - x_left(y)`。
6. 取平均值或中位数。

优点：

- 比方式 2 稳。
- 保留了直线拟合，又降低局部毛刺影响。

缺点：

- 结果仍然是区间统计值，不是单一几何截面。

### 方式 4：旧 C++ 程序的方式，沿参考线法线测量

旧程序文件：

`C:\Users\goney\Desktop\MatchTemplate2\EmbeddingTest\STDC_007_GapSizeWithReflexionArea.h`

关键代码位置：

- `FitLineContourXld` 拟合第一条边：约第 899 行
- `FitLineContourXld` 拟合第二条边：约第 915 行
- 选择较长轮廓作为参考：约第 1186 行
- 把参考线旋转 90° 构造测量线：约第 1198 行
- 测量线分别与两条边求交点：约第 1203 - 1204 行
- 两个交点用 `DistancePP` 算点到点距离：约第 1272 行

旧程序核心逻辑：

```text
1. 拟合两条边缘直线。
2. 选更长的边作为参考线。
3. 在参考线上选一个或多个测量位置。
4. 过该位置做一条垂直于参考线的测量线。
5. 测量线分别与左、右拟合线求交点。
6. 两个交点之间的点到点距离就是宽度。
```

这不是不平行线的最短距离，而是：

```text
沿参考边的垂直方向，测两条拟合线的截面距离。
```

这和卡尺量两个面的宽度最接近。

## 推荐方案

推荐采用旧程序逻辑的改进版：

```text
1. 左 ROI 找边缘点。
2. 右 ROI 找边缘点。
3. 取左右边缘点共同覆盖的 Y 区间。
4. 只保留共同 Y 区间内的边缘点。
5. 分别重新拟合左线和右线。
6. 选择更长、更稳定的线作为参考线。
7. 在参考线中点位置做垂直于参考线的测量线。
8. 测量线分别和左右拟合线求交点。
9. 两个交点之间的距离作为最终距离。
```

如果后续现场仍然有波动，可以扩展为多点测量：

```text
CountGapMultiSize = 3
```

即沿参考线取 3 个位置分别测量，最后取平均值或中位数。默认可以先用 1 个位置，便于解释和对齐旧程序。

## 为什么推荐这个方案

这个方案的优点：

- 符合卡尺测量逻辑：沿一个明确测量方向夹两个面。
- 保留直线拟合，能过滤边缘毛刺。
- 不使用不平行无限直线的“最短距离”概念。
- 和旧 C++ 程序逻辑一致，现场解释成本低。
- 加入共同 Y 区间后，比旧程序更适合当前左右 ROI 高度不一致的情况。

不推荐继续使用当前线段距离逻辑，因为它会把轻微角度抖动放大成几像素的宽度变化。

## 当前上下限配置提醒

当前 `line_distance` 的 JSON 中距离单位是 `px`，但上下限配置为：

```text
lower_limit = 7.9
upper_limit = 8.0
limit_unit = px
```

而实际测量值约为 `1150 px`。如果现场规格是 7.9 - 8.0 mm，应改为：

```text
limit_unit = mm
pixel_size_mm = 实际标定值
lower_limit = 7.9
upper_limit = 8.0
```

否则程序会按像素规格判断，结果一定不符合实际含义。

## 算法代码对应关系

当前配置文件里和尺寸测量相关的 3 个代码不是同一层级：

| 算法代码 | 对应含义 | 是否直接输出距离 | 说明 |
| --- | --- | --- | --- |
| `line_distance` | 距离测量 | 是 | 旧距离计算方式，基于两条已拟合线段的距离计算。 |
| `line_distance_ref_normal` | 卡尺距离测量 | 是 | 参考 STDC007 的思路：选参考线，在参考线法线方向与两条线求交，交点距离作为宽度。 |
| `find_line_subpix` | 高阶亚像素找线 | 否 | 只负责在单个 ROI 内找边并拟合直线；它不是距离测量，需要配合 `line_distance` 或 `line_distance_ref_normal` 使用。 |

所以“高阶亚像素卡尺测量”的配置不是单独一个代码，而是组合：

```text
左线工具：find_line_subpix
右线工具：find_line_subpix
距离工具：line_distance_ref_normal
```

也就是说：

```text
find_line_subpix + line_distance_ref_normal = 高阶亚像素找边 + 卡尺距离测量
```

## 后续代码状态

当前 Python 代码已经增加了两类能力：

1. `line_distance_ref_normal`：参考线法线交点距离，也就是卡尺距离测量。
2. `find_line_subpix`：高阶亚像素找线，用于替代普通 `find_line` 的边缘点提取方式。

主要实现位置：

- 边缘点与拟合逻辑：`algorithms/measurement.py`
- 距离测量组合逻辑：`application/inspection_executor.py`
- UI 为避免误解，不直接暴露 `find_line_subpix`、`line_distance_ref_normal` 等内部算法名称；这些通过 `inspection_items.json` 配置。

当前推荐配置目标：

```text
左/右找线项：find_line_subpix
距离项：line_distance_ref_normal
距离单位：按现场需要设置 px 或 mm
如果使用 mm：必须设置 pixel_size_mm
```

如果后续还需要进一步贴近 STDC007，可以继续增加：

1. 多点法线测量，类似 `CountGapMultiSize`。
2. XLD 风格的共线边缘段合并。
3. 更完整的形状过滤，例如角度、长度、弯曲度、短轴宽度。
