# 皮带线版：共享模型与位置差异训练说明

适用：普通共享功能接入后的 `EmbeddingTest-conveyor` 源码。

## 1. 现有“组训练”是否已经合并样本

皮带线版原来的组训练已经会按同一相机、相同模型键和相同算法，收集各 ROI 的 OK、NG 裁剪样本，训练一个组模型。

这里的合并是把裁剪样本放入同一个训练任务，分别归入 OK 和 NG 类；不会把多个 ROI 拼成一张图片。各 ROI 检测时仍读取自己的位置，分别输出结果。

本次新增明确的模型来源选择：

| 来源 | 样本使用规则 |
| --- | --- |
| 独立训练 | 只使用当前 ROI 的有效训练标注 |
| 同订单组共享 | 同组中启用的 ROI 的有效训练标注合并使用 |
| 引用公共模型 | 使用已发布的固定版本，无须在引用区域重新训练 |

## 2. 不同位置的目标形状、大小不同，能否合并

程序允许合并这些 ROI 的样本。是否适合共用模型，需要看位置差异和实际测试结果。

- 目标类型和缺陷定义一致，位置差异较小：可以尝试共享，并提供各位置有代表性的样本。
- 中央与边缘区域的正常外观差异明显：可以分别建立中央组、边缘组。
- 个别 ROI 的成像条件、判定标准差异较大：选择独立训练。

仅用一个位置的样本训练，不能保证模型适用于所有其他位置。若正常的外观差异没有出现在训练样本中，模型可能将其判断为异常。

例如同一类针可以这样设置：

| ROI | 位置与外观情况 | 模型来源 |
| --- | --- | --- |
| ROI1、ROI2 | 中央区域，正常外观接近 | 共享组 `PIN_CENTER` |
| ROI3、ROI4 | 边缘区域，有相近的位置相关形变 | 共享组 `PIN_EDGE` |
| ROI5 | 外观或判定条件与上述区域差异明显 | 独立训练 |

分组仍需要同一订单、同一相机及相同算法。新配置不会因为模板显示名称相同而强制把已明确选择独立训练的 ROI 改回共享。

## 3. 统一输入尺寸与去畸变的区别

当前训练裁剪流程中：

- Embedding 学习工具将 ROI 裁剪图缩放到 `224 × 224` 后提取特征。
- YOLO 分类工具对 ROI 使用保持比例的 letterbox 缩放、填充。
- 传统判定工具在各自 ROI 内计算灰度、HSV 等特征，再标定阈值。

这些处理统一了模型输入形式，并不等于完成镜头去畸变或透视矫正。本次没有增加相机标定、镜头参数估计或透视矫正流程。

界面中的“标定当前工具”用于当前判定工具的训练或阈值标定，不是镜头畸变标定。

## 4. 两个训练按钮的范围

假设 ROI1、ROI2 属于 `PIN` 组，ROI3 独立，三者都已启用且属于当前相机：

| 操作 | PIN 组 | ROI3 |
| --- | --- | --- |
| 选中 ROI1 或 ROI2，标定当前工具 | 合并 ROI1、ROI2 的有效训练样本，训练一次 | 不训练 |
| 选中 ROI3，标定当前工具 | 不训练 | 使用 ROI3 自身样本训练 |
| 训练全部可训练工具 | 合并 ROI1、ROI2 的有效训练样本，训练一次 | 使用 ROI3 自身样本单独训练 |

共享组整组合计有有效 OK、NG 样本即可开始训练。如果希望覆盖不同位置的正常差异，应为相关位置补充有代表性的标注；同组中已经标注的 ROI 都会参与本次训练。

如果只给 ROI1 准备 OK、NG，其他同组 ROI 保持未标注，系统也允许使用 ROI1 的样本训练一个组模型。其他位置是否适用，需要逐个测试确认。

只有训练样本中存在 ROI 框且已标为 OK、NG 的区域参与训练。测试样本不参与训练，禁用的组成员不贡献训练样本。

## 5. 设置与验证步骤

1. 在检测工具表中选中 ROI，打开“模型来源”或标题旁的“模型来源…”按钮。
2. 根据外观差异选择独立训练或同订单组共享；共享时填写、选择具体组名。
3. 点击“应用模型来源”，逐个检查各 ROI 的来源。
4. 检查训练图片中的 ROI 框，按每个区域的真实状态标注 OK、NG。
5. 标定当前工具或训练全部工具，按界面提示完成框选核对和确认。
6. 使用单独的测试图片，分别检查各位置的正常样本和目标缺陷。
7. 按 ROI 比较误报、漏检情况；共享效果不合适的区域可以拆成另一组，或改为独立训练后重新验证。

训练按钮会先检查并应用当前尚未保存的模型来源选择，组名或版本不完整时会提示补齐。

## 6. 旧订单、旧模型的兼容

旧订单中的 `task_group`、`group_key`、`shared_group` 会按已有组共享关系读取。旧中文组名、旧 ASCII 命名及旧模型文件后缀继续兼容。

原组会单独记录，即使成员都切成独立模式，仍可以选回原组。新组使用独立的模型命名空间，避免与独立 ROI 的模型文件重名。

若旧组模型键与一个独立 ROI 的键相同，保存配置时会为组模型复制出独立保存位置，保留原文件；之后两边重新训练不会互相覆盖。组名和各 ROI 的检测位置保持原有含义。

## 7. 公共模型与跨订单复用

Embedding、传统阈值工具及已有 YOLO 分类工具均可发布、引用公共版本。不同算法的模型不能作为同一个算法直接混用。

1. 在源订单选中已训练的本地模型，点击“发布到公共库”。
2. 选择新建模型，或选择已有模型发布新版本。
3. 在目标订单为 ROI 选择“引用公共模型”，选择模型、固定版本并应用。
4. 检查来源订单、ROI、工具与模型标识后，使用目标订单图片测试。

模型标识相同、版本不同，表示同一模型的不同版本；名称相同、标识不同，表示两个独立模型。发布新版不会自动升级已有引用。

公共版本保留发布时的判定参数；YOLO 分类版本包含 ONNX 与分类元数据，并保留发布时的 NG 阈值。引用区域不需要重新训练，也不能直接覆盖公共版本。

公共模型库保存在本程序的 `.qr_session/model_library` 下。备份整个 `.qr_session` 可以同时带上订单和公共模型库；只复制单个订单时，还需带上它引用的公共库。

## 8. 状态与测试提示

- “未训练”：当前独立 ROI 缺少当前工具对应的模型。
- “未训练（共享组：…）”：组已设置，但缺少当前工具对应的组模型。
- 绿色共享组状态：当前组模型可用。
- 旧格式模型会显示兼容提示；切换学习工具后，会按该工具对应的模型重新检查状态。

离线测试和皮带线运行前都会检查共享模型及公共版本是否可用，缺少模型时会明确提示。程序测试可以验证样本收集、模型引用及 ROI 读取逻辑；实际位置差异下的识别效果，仍需要用现场样本逐项验证。
