# iv4matchmethod 项目介绍与使用说明

## 1. 项目简介

`iv4matchmethod` 是一个围绕“模板条件化轻量定位器”方案搭建的工程原型，目标是支持以下两类能力：

1. 深度定位器主线
   - `MobileNetV3-Small` backbone
   - `depthwise xcorr` 模板相关匹配
   - `heatmap + offset + angle + scale + quality` 多头输出
   - ROI follow
   - 可选 prototype-based OK/NG

2. 免训练配准主线
   - `XFeat + LighterGlue / MNN`
   - 模板图与待测图的特征匹配
   - 基于单应矩阵的 ROI 跟随

当前项目里，**最稳定的免训练路径是 `XFeat + LighterGlue`，更轻量的 CPU 路径是 `XFeat + MNN`**。  
深度定位器框架已经实现，但如果要在真实工业图上稳定工作，仍然需要针对真实数据训练或微调。

## 2. 当前已实现功能

### 2.1 命令行入口

当前 CLI 子命令：

- `annotate-template`
- `annotate-search`
- `match-xfeat`
- `synthesize`
- `train`
- `infer`
- `build-prototypes`

入口模块：

```powershell
python -m iv4matchmethod <subcommand>
```

### 2.2 模板图标注 GUI

用于标注模板图中的：

- `template_bbox`
- `roi_image_polygon`
- `roi_ref_polygon`

适用场景：

- 免训练匹配前，先定义模板和 ROI
- 深度训练前，先定义模板参考坐标系

### 2.3 搜索图标注 GUI

用于给训练数据打标签：

- `center`
- `angle_deg`
- `scale`
- `ok_ng`

适用场景：

- 只有在准备训练深度定位器时才需要

### 2.4 XFeat 匹配

这条路线不依赖你自己的训练数据，适合：

- 已经有模板图和模板 ROI
- 想直接在待测图中跟随同一块区域
- 先验证配准/ROI follow 是否可用

输出包括：

- 匹配可视化图
- ROI 跟随图
- 结果 JSON

当前支持两种 matcher：

- `lighterglue`
  - 更稳
  - 更适合复杂、重复结构较多的图
- `mnn`
  - 更轻
  - 更适合追求 CPU 时延的场景
  - 但对 `180°` 近对称和重复结构更敏感

### 2.5 深度定位器训练与推理

这条路线对应原方案文档中的主线：

- `train` 训练定位网络
- `infer` 推理输出位姿和 ROI
- `build-prototypes` 构建 ROI 原型库用于 OK/NG
- `synthesize` 生成合成数据做 smoke test

说明：

- 当前代码层面已打通
- 真实工业数据要想跑稳，仍需要真实样本训练

## 5. 两条典型使用流程

## 5.1 流程 A：不训练，直接做模板匹配与 ROI 跟随

这是当前最推荐的上手方式。

### 第一步：标注模板图

```powershell
.\.venv\Scripts\python.exe -m iv4matchmethod annotate-template `
  --image D:\Git\matchtemplate\iv4matchmethod\demo_data\user_images\products\6\template.bmp `
  --output D:\Git\matchtemplate\iv4matchmethod\demo_data\user_images\products\6\template_annotation.json
```

标注完成后，通常会得到：

- `template_annotation.json`
- `template_annotation_preview.png`

### 第二步：对单张待测图做匹配

```powershell
.\.venv\Scripts\python.exe -m iv4matchmethod match-xfeat `
  --template-annotation D:\Git\matchtemplate\iv4matchmethod\demo_data\user_images\products\6\template_annotation.json `
  --search-image D:\Git\matchtemplate\iv4matchmethod\demo_data\user_images\products\6\Image_20260206154338279.bmp `
  --output-dir D:\Git\matchtemplate\iv4matchmethod\runs\single_match `
  --max-dim 1024 `
  --top-k 4096
```

如果要改成 `MNN`：

```powershell
.\.venv\Scripts\python.exe -m iv4matchmethod match-xfeat `
  --template-annotation D:\Git\matchtemplate\iv4matchmethod\demo_data\user_images\products\6\template_annotation.json `
  --search-image D:\Git\matchtemplate\iv4matchmethod\demo_data\user_images\products\6\Image_20260206154338279.bmp `
  --output-dir D:\Git\matchtemplate\iv4matchmethod\runs\single_match_mnn `
  --matcher mnn `
  --max-dim 320 `
  --top-k 512
```

输出文件：

- `xfeat_lighterglue_matches.png`
- `xfeat_lighterglue_roi.png`
- `xfeat_lighterglue_result.json`

如果使用 `MNN`，对应文件名前缀会变成：

- `xfeat_mnn_matches.png`
- `xfeat_mnn_roi.png`
- `xfeat_mnn_result.json`

### 第三步：查看结果

重点看：

- `xfeat_lighterglue_roi.png`
- `xfeat_lighterglue_result.json`

如果只是看速度，不想出图和写 JSON：

```powershell
.\.venv\Scripts\python.exe -m iv4matchmethod match-xfeat `
  --template-annotation D:\Git\matchtemplate\iv4matchmethod\demo_data\user_images\products\6\template_annotation.json `
  --search-image D:\Git\matchtemplate\iv4matchmethod\demo_data\user_images\products\6\Image_20260206154338279.bmp `
  --max-dim 512 `
  --top-k 1024 `
  --no-write-visuals `
  --no-write-json `
  --quiet
```

## 5.2 流程 B：准备训练深度定位器

这条路径适合你后续要做真正的轻量深度模型。

### 第一步：先标模板图

仍然使用：

```powershell
python -m iv4matchmethod annotate-template
```

### 第二步：逐张标注搜索图

```powershell
.\.venv\Scripts\python.exe -m iv4matchmethod annotate-search `
  --template-annotation D:\Git\matchtemplate\iv4matchmethod\demo_data\user_images\template_annotation.json `
  --image D:\Git\matchtemplate\iv4matchmethod\demo_data\user_images\search_0001.png `
  --append-manifest D:\Git\matchtemplate\iv4matchmethod\demo_data\train_real.jsonl
```

### 第三步：训练

```powershell
.\.venv\Scripts\python.exe -m iv4matchmethod train `
  --manifest D:\Git\matchtemplate\iv4matchmethod\demo_data\train_real.jsonl `
  --output D:\Git\matchtemplate\iv4matchmethod\runs\real_train
```

### 第四步：推理

```powershell
.\.venv\Scripts\python.exe -m iv4matchmethod infer `
  --checkpoint D:\Git\matchtemplate\iv4matchmethod\runs\real_train\last.pt `
  --template-image D:\Git\matchtemplate\iv4matchmethod\demo_data\images\template_0000.png `
  --template-bbox "[80,88,96,80]" `
  --search-image D:\Git\matchtemplate\iv4matchmethod\demo_data\images\search_0000.png `
  --roi-ref-polygon "[[-20,-12],[20,-12],[20,12],[-20,12]]"
```

## 6. 标注数据格式说明

模板标注 JSON 关键字段：

```json
{
  "template_image": "xxx/template.bmp",
  "template_bbox": [x, y, w, h],
  "roi_image_polygon": [[x1, y1], [x2, y2], ...],
  "roi_ref_polygon": [[dx1, dy1], [dx2, dy2], ...],
  "roi_origin": "template_bbox_center"
}
```

说明：

- `template_bbox`：模板图中完整目标的矩形框
- `roi_image_polygon`：模板图中的 ROI 多边形
- `roi_ref_polygon`：相对 `template_bbox` 中心的 ROI 坐标

训练 manifest 示例：

```json
{
  "template_image": "images/template_0000.png",
  "template_bbox": [80, 88, 96, 80],
  "search_image": "images/search_0000.png",
  "center": [191.5, 144.0],
  "angle_deg": 12.0,
  "scale": [1.05, 0.97],
  "roi_ref_polygon": [[-20, -12], [20, -12], [20, 12], [-20, 12]],
  "ok_ng": "OK"
}
```

## 7. 参数含义

### 7.1 `match-xfeat` 常用参数

- `--template-annotation`
  - 模板标注 JSON
- `--search-image`
  - 待测图
- `--output-dir`
  - 结果输出目录
- `--matcher`
  - `lighterglue` 或 `mnn`
- `--max-dim`
  - 搜索前先把图像最长边缩到该尺寸
- `--top-k`
  - 最多保留多少个关键点
- `--no-write-visuals`
  - 不保存匹配图和 ROI 图
- `--no-write-json`
  - 不保存结果 JSON
- `--quiet`
  - 不在控制台打印结果

### 7.2 `max_dim / top_k` 是什么

例如：

- `1024 / 4096`
- `768 / 2048`
- `512 / 1024`

表示：

- `max_dim = 1024`
- `top_k = 4096`

含义：

- `max_dim` 越大，保留细节越多，但越慢
- `top_k` 越大，关键点越多，但越慢

### 7.3 `lighterglue` 和 `mnn` 怎么选

- `lighterglue`
  - 质量优先
  - 对复杂图更稳
  - CPU 上更慢
- `mnn`
  - 速度优先
  - 更容易压到低时延
  - 但对重复结构和对称结构更容易失配

## 8. 当前性能结论

以下结论来自当前这台机器的实测，环境为：

- Windows
- Python 3.12
- `torch 2.10.0+cpu`
- `cuda_available = False`

### 8.1 `LighterGlue` 纯热路径推理时间

指：

- 模型常驻内存
- 模板特征已缓存
- 不出图
- 不写 JSON

代表图实测：

- `1024 / 4096`: 约 `1686.6 ms`
- `768 / 2048`: 约 `619.6 ms`
- `512 / 1024`: 约 `232.6 ms`

更激进的参数：

- `384 / 512`: 约 `282.3 ms`
- `320 / 512`: 约 `211.8 ms`
- `256 / 256`: 约 `239.1 ms`

结论：

- 当前 CPU + `LightGlue` 路线很难稳定做到 `100 ms`
- `320 / 512` 是当前测试里的一个相对平衡点

### 8.2 `MNN` 纯热路径推理时间

同样指：

- 模型常驻内存
- 模板特征已缓存
- 不出图
- 不写 JSON

在 `products/2 + template180_annotation.json` 上的一张代表图实测：

- `384 / 512`: 约 `189.6 ms`
- `320 / 512`: 约 `82.3 ms`
- `256 / 256`: 约 `85.3 ms`

对应质量指标：

- `384 / 512`: `109 / 17 / 0.1560`
- `320 / 512`: `146 / 41 / 0.2808`
- `256 / 256`: `111 / 27 / 0.2432`

结论：

- `MNN` 确实更轻
- `320 / 512` 已经能把热路径压到 `100 ms` 内
- 但整体稳健性仍然弱于 `LighterGlue`

### 8.3 带结果输出的批量耗时

带出图和写 JSON 时会更慢，因为还包含：

- 绘图
- 文件写入
- 目录管理

例如 `products/6` 的整目录测试：

- `1024 / 4096` 平均约 `2539.2 ms/张`
- `768 / 2048` 平均约 `1247.1 ms/张`
- `512 / 1024` 平均约 `804.7 ms/张`

另外，`products/2 + template_annotation.json + MNN` 的整目录测试：

- `1024 / 4096` 平均约 `6558.9 ms/张`
- `768 / 2048` 平均约 `6596.7 ms/张`
- `512 / 1024` 平均约 `5643.2 ms/张`
- `384 / 512` 平均约 `5293.2 ms/张`

这里的数字高，主要因为它是：

- 每张重新起一个 Python 进程
- 每张重新加载模型
- 每张都要保存结果图和 JSON

## 9. 当前已知限制

### 9.1 180 度旋转歧义

如果目标在 `0° / 180°` 下局部结构近似对称，`XFeat + LighterGlue` 容易出现：

- 数值上看起来还行
- 但 ROI 语义落错位置

这不是简单参数问题，而是结构对称导致的语义歧义。

### 9.2 全局配准对局部 ROI 不一定最优

当前路线是：

- 先全局匹配
- 再把 ROI 一次性映射过去

所以常见情况是：

- 整体框大致正确
- 但 ROI 有小偏差

### 9.3 100ms 级实时性目前未达成

如果是 `LighterGlue` 路线，当前 CPU 还达不到 `100ms`。  
如果是 `MNN` 路线，热路径已经可以接近或进入 `100ms`，但还不等于完整端到端流程也能达到这个量级。  
如果后面要继续压时延，方向更适合转向：

- 小窗搜索
- 更轻的局部匹配后端
- 或训练好的轻量定位器

## 10. 当前建议

如果你现在的目标是“尽快验证模板跟随可不可用”，推荐：

1. 先走 `annotate-template + match-xfeat`
2. 先用单模板或多模板验证可行性
3. 遇到 `180°` 歧义，再考虑多模板或后续判别逻辑

如果你现在的目标是“最终做到轻量化、低时延、可部署”，推荐：

1. 先把真实数据整理成训练集
2. 用当前项目里的深度定位器主线训练
3. 再做加速和部署
