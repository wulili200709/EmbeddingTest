# 测试流程与统一 GUI 使用说明

本文档面向项目使用者，说明当前仓库的主要测试方式，以及如何通过统一 GUI 完成模板创建、模型编辑和查找验证。

## 1. 测试方式概览

当前项目的测试主要分为两类：

1. 批量回归测试  
   使用仓库内置脚本对 `test/case0`、`test/case1`、`test/case2` 的样例数据批量运行，生成结果图和汇总文件。

2. 统一 GUI 交互测试  
   通过一个图形界面完成模板创建、模型编辑和场景查找，适合用户手工调试参数、观察效果和保存结果。

说明：

- 本项目当前不是以 `pytest` 或单元测试为主。
- 主要验证结果来自输出图片、控制台信息和 `summary.yaml`。

## 2. 环境准备

在项目根目录执行：

```bash
py -3 -m pip install -r requirements.txt
```

当前最基本的依赖为：

- `numpy`
- `opencv-python`

## 3. 批量回归测试

### 3.1 robust 模板匹配批量测试

在项目根目录执行：

```bash
py -3 batch_test_from_yaml.py --root .
```

运行完成后，结果会输出到以下目录：

- `test/case0/result_robust`
- `test/case1/result_robust`
- `test/case2/result_robust`
- `test/result_robust/summary.yaml`

可重点查看：

- 每张测试图对应的结果图片
- 每张测试图对应的结果 YAML
- 总汇总文件 `summary.yaml`

### 3.2 line2Dup-like 批量测试

在项目根目录执行：

```bash
py -3 line2dup_python_batch.py --root .
```

运行完成后，结果会输出到以下目录：

- `test/case0/result_line2dup_python`
- `test/case1/result_line2dup_python`
- `test/case2/result_line2dup_python`
- `test/line2dup_python/summary.yaml`

建议重点检查：

- 输出结果图中目标是否被正确圈出
- 相似度和匹配数量是否符合预期
- 不同 case 的结果是否稳定

## 4. 统一 GUI 入口

如果需要通过图形界面进行测试和操作，在项目根目录执行：

```bash
py -3 line2dup_template_workbench.py
```

该命令会启动统一 GUI 工作台，用于以下三个场景：

- 创建模板模型
- 编辑已有模型
- 在场景图中查找目标

## 5. GUI 主要功能

统一 GUI 包含三个页签：

### 5.1 Create Template

用于从原始图片中创建模板模型。

主要流程：

1. 打开待处理图片。
2. 在图片中拖拽选择 ROI。
3. 调整特征点提取相关参数。
4. 检查并微调模板点。
5. 保存模型。

适用场景：

- 第一次制作模板
- 重新生成模型
- 调整角度、缩放范围和特征点数量

### 5.2 Edit Model

用于打开已有模型并进行修正。

主要流程：

1. 加载已有模型文件。
2. 如有需要，同时加载模板图。
3. 手工增删特征点。
4. 保存修改后的模型。

适用场景：

- 修正自动生成的模板点
- 微调边缘点分布
- 对已有模型做小范围修改

### 5.3 Find

用于使用已保存模型在场景图中执行查找，并观察可视化结果。

主要流程：

1. 加载模型文件。
2. 加载待检测场景图。
3. 调整阈值、NMS 等参数。
4. 执行匹配。
5. 保存结果图。

适用场景：

- 验证模型在真实图片上的检测效果
- 对比不同参数下的结果
- 输出可视化结果供人工确认

## 6. GUI 常见操作

在 GUI 中，常见交互包括：

- 鼠标左键拖拽：选择 ROI 或添加方向点
- 鼠标右键：删除最近的点
- 鼠标滚轮：缩放视图
- 面板参数调整：修改阈值、角度范围、缩放范围、特征数等

不同页签的具体控件会略有差异，但整体流程保持一致：先加载输入，再调参数，最后保存结果。

## 7. 推荐使用顺序

建议按以下顺序使用本项目：

1. 先安装依赖并确认环境可运行。
2. 先执行批量回归测试，确认仓库内置样例结果正常。
3. 再启动统一 GUI，使用自己的图片和模型进行交互式验证。
4. 如结果不理想，可在 GUI 中调整参数或编辑模板点后重新测试。

## 8. 结果检查建议

无论是批量测试还是 GUI 测试，建议重点关注以下内容：

- 目标是否被正确定位
- 误检数量是否可接受
- 检测框、轮廓或特征点是否覆盖目标主体
- 相似度阈值调整后结果是否稳定
- 保存出的模型和结果图是否符合预期

## 9. 常见问题

### 9.1 GUI 无法启动

请先确认：

- Python 版本可用
- 依赖已正确安装
- 本机支持图形界面显示

### 9.2 图片无法读取

请检查：

- 文件路径是否正确
- 图片格式是否受 OpenCV 支持
- 路径中是否存在无法访问的目录

### 9.3 匹配结果不稳定

建议优先尝试：

- 更换更清晰的模板区域
- 调整特征点数量
- 调整角度范围和缩放范围
- 调整查找阈值和 NMS 参数
- 在 `Edit Model` 中手工修正关键点

## 10. 总结

当前项目推荐的测试方式是：

- 用批量脚本做基础回归验证
- 用统一 GUI 做日常使用、参数调试和结果确认

如果只是面向普通用户使用，优先推荐直接从统一 GUI 入口开始。
