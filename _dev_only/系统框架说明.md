# EmbeddingTest 系统框架说明

## 1. 文档目的

这份文档用于回答两类问题：

1. 这个系统整体是怎么组织的。
2. 某个功能以后应该去哪里改。

当前工程已经不是单文件脚本，而是一个分层的 PySide6 桌面系统。主线可以概括为：

- `Main.py` 启动整个应用。
- `ui/` 负责界面。
- `application/` 负责流程编排和业务控制。
- `domain/` 负责核心数据模型。
- `algorithms/` 负责算法能力。
- `line2dup/` 负责模板定位和自动 ROI。
- `services/` 负责运行链路服务。
- `devices/` 负责相机 / IO / 灯控等硬件封装。
- `infrastructure/` 负责配置与持久化对象。
- `.qr_session/` 负责产品运行数据和调试产物落盘。

## 2. 当前主入口和启动链路

### 2.1 主入口

- `Main.py`
  - 当前系统正式入口。
  - 只做一件事：调用 `ui.shell.main_window.main()`。

### 2.2 启动链路

当前实际运行链路如下：

`Main.py`
-> `ui/shell/main_window.py`
-> `ui/window_common.py`
-> 创建 `ProductSession` + `AlgorithmController`
-> `ui/shell/layout.py` 组装主界面
-> 创建 `ToolPage`（调试页）和 `RuntimeModePage`（运行页）
-> 创建 `RuntimeController`
-> 通过 `ui/shell/runtime_bridge.py` 做调试页和运行页之间的跨组件协同

### 2.3 当前真正的主窗口

- `ui/shell/main_window.py`
  - 当前系统真正的总壳窗口。
  - 同时容纳调试工作区和运行工作区。
  - 负责跨页面协同、运行控制器接线、菜单栏、状态栏、会话切换、启动预热。

### 2.4 其他两个窗口入口的定位

- `ui/debug_main_window.py`
  - 独立调试窗口。
  - 更像轻量调试入口，不是当前正式主入口。
- `ui/runtime/run_main_window.py`
  - 独立运行窗口。
  - 适合只验证运行链路，不是当前正式主入口。

## 3. 系统分层理解

建议按下面这套方式理解代码：

- `ui`
  - 用户界面，Qt 控件、布局、对话框、信号连接。
- `application`
  - 把 UI 操作转成业务动作，协调算法、会话、运行时服务。
- `domain`
  - 描述“检测项、检测结果、运行结果聚合”这些纯数据结构。
- `algorithms`
  - 真正做特征提取、传统阈值计算、labelme 标注读写、定位算法。
- `line2dup`
  - 模板编辑、模板匹配、参考 ROI 跟随、自动生成 ROI。
- `services`
  - 相机抓图、运行状态机、记录写入、权限和放行逻辑。
- `devices`
  - 实际硬件访问层，贴近 NKIO / 海康相机 / 灯控。
- `infrastructure`
  - 配置存取、产品参数存取、相机参数存取。

可以把它理解成：

- `ui` 决定“怎么显示”
- `application` 决定“怎么调度”
- `domain` 决定“系统里有哪些业务对象”
- `algorithms / line2dup / services / devices` 决定“事情到底怎么做”

## 5. 按目录拆解源码职责

## 5.1 `algorithms/`

这个目录提供“算法能力本身”。

- `algorithms/api.py`
  - 算法聚合出口。
  - 上层一般通过它或 `proxy.py` 间接调用算法。
- `algorithms/proxy.py`
  - 懒加载代理层。
  - 避免应用启动时直接重载算法引擎。
  - 如果你想看“上层到底在调谁”，这个文件是入口之一。
- `algorithms/embedding.py`
  - 学习型算法主实现。
  - 包含 backbone 加载、ROI embedding、proto / topk 预测等。
  - 改 embedding 推理、特征提取、topk/proto 逻辑时改这里。
- `algorithms/traditional.py`
  - 传统阈值算法实现。
  - 包含 HSV / 灰度统计、阈值训练、传统模型预测。
  - 改传统工具算法时改这里。
- `algorithms/registry.py`
  - 算法注册表。
  - 定义可选算法、显示名、算法家族、工具算法编码。
  - 新增算法时，通常先改这里。
- `algorithms/localization.py`
  - 基于图像匹配的定位辅助能力。
  - 包含模板定位、ORB 对齐等。
- `algorithms/labelme.py`
  - labelme 标注文件读写。
  - 包含 ROI shape 的读、写、替换、删除。
  - 改标注 JSON 格式处理时改这里。
- `algorithms/__init__.py`
  - 包导出层，给上层统一 import。

## 5.2 `application/`

这个目录负责“把页面操作编排成业务动作”。

- `application/algorithm_controller.py`
  - 算法控制中心。
  - 负责产品算法参数、模型加载、训练、预测。
  - UI 不应该直接拼训练 / 预测逻辑，应该通过这里。
- `application/product_session.py`
  - 产品和会话管理中心。
  - 负责 `products.json`、当前产品目录、`session.json` 读写。
  - 改产品切换、会话恢复、产品目录规则时改这里。
- `application/inspection_executor.py`
  - 运行时检测执行器。
  - 把“某张图 + 某些检测项”执行成 item 级 / camera 级结果。
- `application/runtime_context.py`
  - 运行时上下文协议。
  - 定义 RuntimeController 依赖的最小能力接口。
  - `ToolPageRuntimeContext` 用于调试页接入运行链路。
  - `ProductRuntimeContext` 用于独立运行窗口。
- `application/runtime_controller.py`
  - 兼容入口。
  - 实际实现已经下沉到 `application/runtime/controller.py`。
  - 正常情况下不要把新逻辑继续堆在这个兼容文件里。
- `application/__init__.py`
  - 统一导出应用层符号。

### 5.2.1 `application/runtime/`

这是 RuntimeController 的真实拆分目录。

- `application/runtime/controller.py`
  - 运行链路主控制器。
  - 管理相机、抓图、运行触发、放行、状态广播、结果输出。
- `application/runtime/bindings.py`
  - 把运行控制器拆分方法绑定回类。
  - 作用类似“运行控制器子模块注册表”。
- `application/runtime/capture_policy.py`
  - 运行抓图保留策略。
  - 定义保留全部 / 仅保留 NG 的策略与清理逻辑。
- `application/runtime/execution.py`
  - 运行执行辅助逻辑。
  - 处理预检、抓图落盘、结果收尾、运行记录写入。
- `application/runtime/hardware.py`
  - 运行时硬件装配逻辑。
  - 负责创建 IO 控制器、重建 runner、脚踏触发接入等。
- `application/runtime/status_bus.py`
  - 运行时状态广播逻辑。
  - 把运行状态、相机结果、检测项状态转成 UI 可消费的数据。
- `application/runtime/__init__.py`
  - 子包导出层。

## 5.3 `domain/`

这个目录放“系统内部的业务模型和纯规则”。

- `domain/inspection_items.py`
  - 检测项配置模型。
  - 一个 ROI 对应一个 `InspectionItem`。
  - 负责 `inspection_items.json` 读写与 label 同步。
- `domain/inspection_models.py`
  - 运行检测结果模型。
  - 定义 item 级、camera 级、runtime 级结果结构。
- `domain/result_aggregator.py`
  - 运行结果聚合器。
  - 把 camera 结果聚合成最终运行结果。
- `domain/recipe_manager.py`
  - 与 line2dup recipe / ROI 标签管理相关的纯业务规则。
  - 包括输出 ROI 标签、可清空标签等。
- `domain/__init__.py`
  - 统一导出领域模型。

## 5.4 `services/`

这个目录是运行链路的服务层，不直接做 UI。

- `services/camera.py`
  - 海康相机封装。
  - 包含相机枚举、连接、取图、参数设置、图像格式转换。
  - 改相机 SDK 对接、曝光 / 增益 / 软触发时改这里。
- `services/inspection_runtime.py`
  - 最小运行时检测管线。
  - 负责采图顺序、并发检测、灯控时序、结果输出。
- `services/inspection_scheduler.py`
  - 运行调度器。
  - 负责触发是否允许、NG 锁定、放行消耗。
- `services/permission_manager.py`
  - 放行密码与 NG 锁逻辑。
- `services/run_state.py`
  - 运行状态机定义。
  - 包含状态枚举和合法转移约束。
- `services/record_writer.py`
  - 运行记录和放行日志 CSV 写入。
- `services/__init__.py`
  - 统一导出服务层符号。

## 5.5 `devices/`

这个目录是硬件设备层，偏底层。

- `devices/io_manager.py`
  - IO 管理器，高层 IO 入口。
- `devices/io_controller.py`
  - IO 控制抽象 / 实现支撑。
- `devices/io_mapping.py`
  - IO 通道映射定义。
- `devices/di_monitor.py`
  - 数字输入监视，适合脚踏开关等事件化监听。
- `devices/di_poller.py`
  - DI 轮询逻辑。
- `devices/light_controller.py`
  - 光源控制。
- `devices/tower_light_controller.py`
  - 三色塔灯控制。
- `devices/nkio_board.py`
  - NKIO 板卡封装。
- `devices/nkio_raw.py`
  - 更底层的 NKIO 原始调用封装。
- `devices/nkio_errors.py`
  - NKIO 错误定义。
- `devices/__init__.py`
  - 硬件包导出层。

如果你要改的是“真实脚踏触发 / 灯控 / DO 输出 / IO 板卡通道”，先看这个目录。

## 5.6 `infrastructure/`

这个目录负责“配置对象的读写”，不是业务流程本身。

- `infrastructure/product_params.py`
  - 产品级算法参数存储。
  - 保存 `algorithm / learning_backbone / score_mode / margin / topk / traditional_models`。
- `infrastructure/camera_settings_store.py`
  - 相机参数存储。
  - 保存按序列号区分的曝光、增益、触发模式等。
- `infrastructure/__init__.py`
  - 包导出层。

## 5.7 `line2dup/`

这个目录是模板定位和自动 ROI 子系统。

### 5.7.1 `line2dup/core/`

- `line2dup/core/recipe.py`
  - 模板 recipe 数据结构和读写。
- `line2dup/core/locator.py`
  - 对外主入口。
  - 负责按产品目录组织 `line2dup_model.json` 和 `line2dup_recipe.json`。
  - 也负责自动 ROI 输出。
- `line2dup/core/roi_follow.py`
  - 参考 ROI 跟随。
  - 把参考图上的区域映射到目标图。
- `line2dup/core/template_core.py`
  - 模板构建底层逻辑。
- `line2dup/core/bootstrap.py`
  - 启动或辅助装配逻辑。
- `line2dup/core/__init__.py`
  - 子包导出层。

### 5.7.2 `line2dup/ui/`

- `line2dup/ui/template_page_pyside6.py`
  - 模板编辑器界面。
  - 改参考区域编辑、模板保存界面时看这里。

### 5.7.3 `line2dup/__init__.py`

- 子系统包说明，不含核心逻辑。

## 5.8 `ui/`

这个目录是所有界面代码。

### 5.8.1 `ui/shell/`

这是当前系统正式主界面壳层。

- `ui/shell/main_window.py`
  - 正式主窗口。
  - 创建 `ProductSession`、`AlgorithmController`、`ToolPage`、`RuntimeController`、`RuntimeModePage`。
  - 负责总启动逻辑、工作区切换、关闭收尾。
- `ui/shell/layout.py`
  - 主窗口布局搭建。
  - 把调试页和运行页放进同一个壳窗口。
- `ui/shell/chrome.py`
  - 菜单栏、顶部工具栏、状态栏、品牌栏等壳层 UI。
- `ui/shell/dialogs.py`
  - 密码、相机绑定等弹窗。
- `ui/shell/runtime_bridge.py`
  - 调试页和运行页之间的桥接逻辑。
  - 包含产品切换、会话清空、运行相机绑定、运行抓图策略同步。
- `ui/shell/engine.py`
  - 算法引擎预热、调试会话重载、当前模型预加载等壳层辅助逻辑。
- `ui/shell/support.py`
  - 应用名、图标、资源路径、Windows App ID 等基础支持。
- `ui/shell/__init__.py`
  - 壳层包导出。

### 5.8.2 `ui/debug/`

这是调试页相关 UI。

- `ui/debug/tool_page_pyside6.py`
  - 兼容包装文件。
  - 实际逻辑已转到 `ui/debug/tool_page/page.py`。
- `ui/debug/roi_canvas_pyside6.py`
  - ROI 画布和 overlay 绘制。
  - 改框选、多边形标注、图上叠加显示时看这里。
- `ui/debug/embedding_analysis_dialog.py`
  - embedding 分析对话框。
- `ui/debug/__init__.py`
  - 调试页懒加载导出。

### 5.8.3 `ui/debug/tool_page/`

这是调试页的真实实现目录，也是当前改动最频繁的地方。

- `ui/debug/tool_page/page.py`
  - ToolPage 主文件。
  - 负责调试页 UI 组装、状态持有、对外公开方法。
  - 如果不确定某个调试功能从哪里进，先看这个文件。
- `ui/debug/tool_page/bindings.py`
  - ToolPage 子模块绑定注册表。
  - 把散落在多个文件的方法绑定回 `ToolPage`。
  - 这个文件更像“目录索引”。
- `ui/debug/tool_page/roi_ops.py`
  - ROI 相关操作。
  - 包含图像加载、当前 ROI 读取、overlay 刷新、标注载入。
- `ui/debug/tool_page/auto_roi.py`
  - 自动 ROI 和检测项同步相关的纯辅助逻辑。
  - 包括 line2dup 输出标签、缺失 ROI 检测、检测项同步。
- `ui/debug/tool_page/auto_roi_flow.py`
  - 自动 ROI 流程逻辑。
  - 包括参考图设置、模板页打开、自动生成 ROI、批量清理 ROI。
- `ui/debug/tool_page/tool_config.py`
  - 检测工具表配置。
  - 改工具表列、相机列、算法列、检测项持久化时看这里。
- `ui/debug/tool_page/test_runner.py`
  - 测试执行和结果表。
  - 包括单图预测、结果表填充、日常测试日志写入。
- `ui/debug/tool_page/analysis_tools.py`
  - 分析和报表工具。
  - 包括 margin 建议、test export、传统基线分析报表。
- `ui/debug/tool_page/camera_debug.py`
  - 调试相机页面辅助逻辑。
  - 包括调试相机参数读取、预览显示、设置存储。
- `ui/debug/tool_page/debug_camera_flow.py`
  - 调试相机完整流程。
  - 包括连接、断开、实时预览、抓图、调试 IO。
- `ui/debug/tool_page/__init__.py`
  - 子包导出。

## 6. `.qr_session/` 目录结构说明

这个目录非常重要，因为很多“改动到底有没有生效”最后都体现到这里。

- `.qr_session/products.json`

  - 全局级别会话数据。

- `session.json`
  - 该产品 OK/NG/TEST 文件列表、参考图、定位方式、运行相机序列号等。

  - line2dup 模板模型。
- `line2dup_recipe.json`
  - line2dup recipe。
- `register_model_*.npz`
  - embedding 注册模型。
- `runtime_capture/`
  - 运行抓图。
- `runtime_records/`
  - 运行记录 CSV。
- `release_logs/`
  - 放行日志 CSV。
- `test_logs/`
  - 调试页单图测试日志。

  - 调试页测试导出报表。

  - margin 验证报表。

## 10. 当前系统的几个关键判断

- 正式入口是 `Main.py -> ui/shell/main_window.py`
- `ui/debug/tool_page/` 是当前调试页主战场
- `application/runtime/` 是当前运行链路主战场
- `algorithms/` 和 `line2dup/` 是算法和自动 ROI 的核心能力层
- `legacy/` 不是正式主链路
- `.qr_session/` 里的文件是很多功能最终生效的真实落点

## 11. 后续维护建议

- 改 UI 时，先确认是不是只改壳层，还是会影响 `application/` 和 `.qr_session/` 落盘。
- 改算法时，优先先看 `registry.py`、`algorithm_controller.py`、对应算法实现，避免只改 UI 下拉框。
- 改运行链路时，尽量从 `RuntimeController -> services -> devices` 这条线去看，不要直接在 UI 层补业务。
- 新增功能优先放在现用目录，不要继续往 `legacy/` 里堆。
- 如果修改了 session、检测项、模型文件格式，必须同步检查 `.qr_session/` 下已有产品目录的兼容性。
